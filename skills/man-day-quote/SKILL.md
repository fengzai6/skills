# 人天报价

按固定表结构拆工作项并生成报价 xlsx。

## 硬规则

- **开始前必问**：调用本 skill 后、动手前，先向用户确认缺失项（方式、落地路径）；用户已写明的不问。未齐则停：不拆行、不估人天、不写 xlsx、不猜历史路径
- **类型列用繁体枚举**（见下）；**报价明细优先简体**
- **人天只允许 0.5 步长**（0.5、1、1.5…）；无依据不报 ≥2
- **出 xlsx 前必须用户确认明细**（对话表确认后才跑脚本）；用户明确「直接出文件」可跳过
- **落地路径（必要）**：须用户指定**输出目录**（或完整输出文件路径）；不擅自写到临时目录或猜历史项目路径
- **附近参考（可选）**：在落地路径同目录及常见子目录扫已有报价 xlsx；**有则参考口径，没有就跳过**，只用本 skill 锚点与拆行规则
- **模板（可选）**：用户若额外提供模板 xlsx → `-t` 优先用；未提供 → 脚本内建表头+公式+类型下拉
- 不写单价/税费/商务条款（本表只有人天）
- Total 用 `SUM(E:E)` 公式，不手写死总数充数

## 类型枚举（写入 C 列，繁体；与模板下拉一致）

`邏輯` | `軟件接口對接` | `頁面` | `定義一個實體（含CURD）` | `定義一個實體的DBUP` | `接口` | `硬件接口對接` | `硬件集成` | `Discount`

xlsx 的 C 列带下拉（脚本写入）。禁止长期空类型。识别历史简体时映射到上表再写入。

## 人天锚点（参考，非死公式）

| 典型工作 | 人天 |
|----------|------|
| 单接口对接 / CRUD 壳 / 单表 DBUP / 小块 UI | 0.5 |
| 带状态的页面或中等逻辑 | 0.5–1 |
| 权限/并发/多端通知/较复杂计算 | 1–1.5 |
| 定时+事务+抢占等硬逻辑 | ~2（明细须能看出复杂度） |

中位数历史约 0.5；≥2 必须少用。

## 两条线

### 线 A：直接报价

需求已能拆成可验收工作项 → 直接拆行 → 对话确认 → 生成 xlsx。

### 线 B：先设计再报价

需求糊、范围不清 → **先把需求/方案谈清楚**，再回到本 skill 拆行报价。设计工具按可用性降级，只走能用的那一层：

1. **有 superpowers** → 用其设计流（如 `brainstorming`）
2. **无 superpowers、有 openspec** → 用 openspec 把范围/方案写清
3. **两者都无** → 尝试 `task-planner`（按该 skill 自身触发条件，能轻则轻）
4. 设计产物足以拆成可验收工作项后 → 回到线 A 的拆行 → 确认 → 出表

## 拆行规则

- 一句明细 = **一个可验收工程动作**（对象 + 动作）
- 同一 FR：頁面 / 邏輯 / 接口 / 對接 **分多行**
- 前后端分开估 → **分文件**（文件名带 `-api` / `-web`）
- 功能列：`FR-xx`，可 `FR-04/05`，可 `FR-06（phase2）`

## 表结构

| 列 | 内容 |
|----|------|
| A 序号 | 1,2,3…（确认后写文件时补全连续） |
| B 功能 | FR 号 |
| C 类型 | 繁体枚举 |
| D 报价明细 | **优先简体**，一句一事 |
| E 人天 | 0.5 步长 |
| F | 空 |
| G | 表头 `Total`；G2=`=SUM(E:E)` |

## 工作流

1. **开始前必问**（调用后立刻问，未齐不往下）。缺什么问什么：
   - **方式**：线 A 直接报价 / 线 B 先设计再报价
   - **落地路径**：输出目录或完整 xlsx 路径
2. **可选参考**：落地路径附近扫已有报价 xlsx；有则参考口径，无则跳过
3. 按已确认方式走线 A 或线 B；线 B 先设计至范围可拆
4. 拆行（类型∈枚举、人天∈0.5 刻度、明细非空；有参考时对齐其口径）
5. **对话中输出确认表**（序号/FR/类型/明细/人天 + 总人天），等用户 OK
6. 用户确认后调用生成脚本，`-o` 指向落地路径；仅当用户另给了模板时加 `-t`
7. 回报路径、行数、总人天；可选按类型小计

### 生成命令

脚本：本 skill 目录 `scripts/generate-quote-xlsx.py`。从 `man-day-quote` skill 目录执行；缺少依赖时先安装：

```bash
python3 -m pip install openpyxl
```

```bash
# 用户模板优先
python3 scripts/generate-quote-xlsx.py \
  -t "/path/to/用户模板.xlsx" \
  -i rows.json \
  -o "产品 V1.0 - 需求简称-web 的报价.xlsx"

# 无用户模板：脚本内建表头+公式
python3 scripts/generate-quote-xlsx.py -i rows.json -o out.xlsx
```

`rows.json`：

```json
{
  "rows": [
    {"seq": 1, "feature": "FR-01", "type": "邏輯", "detail": "认领并发控制", "days": 1}
  ]
}
```

文件名建议：`{产品} {版本} - {需求简称}[-api|-web] 的报价.xlsx`

## 确认表格式（给用户看）

```markdown
| 序号 | 功能 | 类型 | 报价明细 | 人天 |
|------|------|------|----------|------|
| 1 | FR-01 | 邏輯 | … | 0.5 |
**合计**: N 人天
```

等用户确认后再生成文件。

## 红线

- 未问清方式或落地路径就开始拆行 / 估人天 / 写 xlsx
- 无落地路径就写 xlsx（应先问输出目录/文件路径）
- 未确认明细就写 xlsx（除非用户声明直接出）
- 类型用简体写入或留空
- 人天出现 0.3、1.2 等非 0.5 步长
- 线 B 未设计清楚就强行报整数大包
- 用户给了模板却不用、改用内建
- 把某个固定历史项目写死进 skill 当唯一口径

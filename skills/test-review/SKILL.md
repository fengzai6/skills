# 测试完备性审查

评判相对本次改动的测试是否够用；**有阻塞则自行补最小测试**。

- 不管「命令有没有跑通」→ `verification-before-completion`
- 不管「要不要先写测试再写代码」→ TDD

> **给执行者**：**只做下方工作流**。禁止再派子智能体套娃。

## 硬规则（与 main 测试规范一致）

- **无测试依赖则不写、不逼写**：未引入 Jest / Vitest / pytest 等 → `N/A - 无测试依赖`，结束
- **优先**：有分支、循环、状态、错误处理或业务不变量的逻辑；**非必要不写 UI 测试**（除非用户要求）
- **简单逻辑不写、不算阻塞**（映射/透传/委托/单行转换/无分支无循环无状态/纯展示/配置/类型/re-export，或测试只能复述实现）；不为凑覆盖率堆测试。判断对象是行为是否简单，不是「是不是函数」
- **禁止**在测试里重写业务逻辑；必须引用被测实现
- **禁止**对未确认行为凭空写断言；行为不确定 → 标 `需用户确认`，**不要瞎补**
- **阻塞缺口：自行补最小测试**（有测试依赖时）；用户明确跳过除外。简单逻辑缺口不算阻塞
- **建议项**：可列在报告里，不强制大改

## 工作流

1. **看改动**：本次行为与边界（含错误路径）
2. **看项目**：测试依赖与现有测试惯例
3. **无测试依赖** → 报告 N/A，结束
4. **有依赖** → 按下方维度审查
5. **出报告**（分级）
6. **有阻塞** → **立即**补最小测试（或用户已声明跳过）→ 更新报告结论
7. 补测后的「跑通」由 verification-before-completion 负责；本 skill 不替代跑命令
8. **返回**仅用下方报告结构（外加补测文件列表）；不写长叙事

## 审查维度

| 维度 | 问什么 |
|------|--------|
| 主路径 | 新/改行为是否至少有一条会失败的断言？ |
| 边界/错误 | 真实风险下的空值/非法输入/失败分支？ |
| 回归 | bugfix 是否锁住复现条件？ |
| 定位 | 行为 vs 实现细节？ fragile mock 是否过多？ |
| 冗余 | 是否重复或测无收益的简单代码？ |
| 规范 | 是否重写业务逻辑、猜测断言、多余 UI 测？ |

## 报告格式（执行完毕只回这个）

```markdown
## 测试审查

**结论**: 通过 | 已补测 | 需用户确认 | N/A - 无测试依赖

### 阻塞
- [文件/行为] 问题 → 已补 / 待补：...

### 建议
- ...

### 可减免
- ...（理由）

### 补测改动（如有）
- path/to/file.test.ts
```

- **通过**：无阻塞
- **已补测**：曾有阻塞，已写最小测试
- **需用户确认**：行为含义不清，无法诚实写断言
- **N/A**：无测试栈

## 红线

- 执行本 skill 时再派子智能体（套娃）
- 无测试依赖仍补测或逼写
- 把「已有测试绿了」当成「相对本次改动已完备」
- 阻塞未处理（也未获用户跳过）就当作通过
- 为凑数写 UI 测、给简单逻辑补测，或在测试中重写业务逻辑

# Agent Note: 人天报价的固定估算与明细口径

Status: implemented

## Problem

本次修改前，`man-day-quote` 将接口和 DBUP 的 0.5 人天作为参考锚点，历史报价可以改变估算值；报价方式的提问和逻辑明细示例也未给出用户要求的说明与命名口径。

## Decision

- 每个接口、每个 DBUP 脚本固定为 0.5 人天，固定值优先于历史参考；独立业务逻辑仍单列估算。
- 提问时解释直接报价适用于范围清晰的需求，先设计再报价适用于需要澄清范围和方案的需求，不只提供线 A/B 标签。
- 接口明细以“接口”结尾，逻辑明细以“逻辑开发”结尾，并同步示例。
- 本次在 skill 指令层约束拆项和确认表，不修改通用 xlsx 生成脚本。

## Alternatives considered

沿用参考锚点能适配历史报价差异，但不能保证接口和 DBUP 固定为 0.5 人天，因此不采用。

## Verification

- 检查 `SKILL.md` 的固定人天、方式说明、明细后缀和示例。
- 从仓库根目录使用 Node.js 运行 `write-notes-like-deepseek` 的目录、格式、归档校验脚本；使用 `git diff --check` 检查差异。
- 独立场景验证覆盖方式和路径缺失、已知范围直接报价、历史参考与固定人天冲突三种情况。

## Consequences

固定人天和明细后缀让对话确认表采用一致口径，用户也可以根据说明选择报价方式。生成脚本不校验业务命名和固定人天，仍需代理在拆项与确认表阶段遵守指令。

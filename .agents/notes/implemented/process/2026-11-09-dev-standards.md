# Agent Note: 全局对话规则与开发规范按任务分离

Status: implemented

## Problem

本轮修改前，`rules/main.md` 为 5,087 tokens（`cl100k_base`），README 要求将其作为全局规则加载。文件同时包含对话偏好、默认开发闭环、代码规范和开发 skill 路由，普通对话也会接收开发流程要求。工作目录是否存在代码仓库不能可靠代表当前任务是否涉及开发。

## Decision

- 将开发闭环、任务分流、项目风格、未提交实现调整边界、代码规范、开发决策笔记和专项 skill 路由迁入 `dev-standards`。入口明确以任务内容判断，在相关分析或操作前读取。
- 开发闭环、任务分流和决策笔记与代码规范统一放在 `SKILL.md`，一次读取即可获得本 skill 的完整规则；这些内容每次开发任务都需要，不另设必读参考文件。
- `main` 保留中文回复、事实查证、关键歧义确认、范围约束、Git 授权、内容真实性、工具规则及既有安全章节；纯概念问答不默认进入开发流程。
- 跨开发项目通用的规则归 `dev-standards`，跨对话场景的规则归 `main`；同步仓库归属说明及 README。
- 保留本轮开始时已有的后端规范草稿与提案，不接入其触发路由；只调整本仓库文件。

既有[规范归属边界](../../implemented/process/2026-11-03-main-rules-ownership.md)部分重叠：本决策调整通用开发约束的加载位置，原有专项承接关系继续适用。[查证确认与文件拆分边界](../../implemented/process/2026-11-03-main-rules-execution-boundaries.md)、[按技术栈命名](../../implemented/process/2026-11-03-stack-aware-naming.md)和第一轮去重记录保留其独立决定，不归档；后端提案属于独立领域草稿。

## Alternatives considered

- **保留在 main，仅补章节适用条件（未采用）**：修改少、无需额外发现入口，但开发正文仍常驻，不能减少普通对话接收的无关内容。
- **main 保留通用规则，开发规范按任务加载（采用）**：适用边界与内容加载一致，允许仓库内普通对话和无仓库开发任务分别处理；代价是必须维护明确的触发入口与专项路由。

## Verification

- 对照本轮修改前的工作区快照，逐项核对命名、复用、拆分、模块化、测试和决策笔记正文的承接；全局内容真实性要求、Git 授权条款及工具和安全章节完整保留，原有 10 个 skill 引用仍有入口。
- 技能正文为 111 行，开发闭环及决策笔记已内联；逐行核对合并前的规则正文均有保留，移除原参考文件及其读取要求。使用 `skill-creator` 已有 `quick_validate.py` 校验 frontmatter 与命名，并核对正文相对链接。
- 人工核对仓库内普通写作、无仓库写脚本、纯概念解释、项目开发方案、对话任务切换、业务规划与报价六类触发场景；这不代表独立代理行为测试。
- 从仓库根目录运行 `node scripts/count-tokens.mjs`：`main` 从本轮修改前的 5,087 tokens 变为 1,945 tokens；`dev-standards` 单文件为 3,525 tokens，口径均为 `cl100k_base`。
- 从仓库根目录使用现有 Node.js 24 执行已安装笔记 skill 的目录、格式和归档校验脚本，三项均通过；运行 `git diff --check` 通过，不新增仓库依赖或工具链。
- 核对本轮开始时已有后端草稿、提案与 README 待审阅说明，文件哈希或正文与快照一致。

## Consequences

- 全局入口只携带跨对话约束和任务路由，开发正文按任务加载；开发任务仍使用原有确认、文件拆分、测试及笔记边界。
- 开发任务一次读取本 skill 即可获得全部通用开发规则，代价是 `SKILL.md` 为 111 行，超过仓库通常采用的 100 行建议；这些规则每次都需读取，保持单文件可减少一次读取及漏读风险。
- 维护者需要同时核对全局入口和开发专项入口，新增规则须先判断对话、开发或领域归属。
- 纯概念问答不默认进入开发流程；一旦涉及具体实现或开发决策，须重新判断并加载。若实际使用出现误触发或漏触发，应根据具体请求调整边界。
- 路由文本、结构检查和人工场景推演不能证明未来代理始终正确触发；本轮没有独立代理行为测试。运行时副本不会随仓库修改自动更新。

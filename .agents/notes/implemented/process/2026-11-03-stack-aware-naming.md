# Agent Note: 通用命名规则按项目与技术栈确定

Status: implemented

## Problem

本次修改前的 `rules/main.md` §2.1 对所有项目统一要求文件与目录使用 `kebab-case`、常量使用 `UPPER_CASE`。用户反馈 C# 项目也因此使用了烤串风格文件名；通用入口的具体大小写要求会干扰其他语言和框架的惯例。

## Decision

- 文件、目录和代码符号遵循目标项目的明确规范；没有明确规定时，采用所属语言或框架的惯例及对应专项 skill，不全局统一大小写风格。
- 混合技术栈按文件或模块的归属分别执行，不把一种语言的风格套用到其他语言。
- 保留通用产物按功能或用途命名的原则，不再以具体技术栈的示例表达该通用原则。
- 本次只调整通用入口及 README 统计，不改专项 skill、不新增 C# skill、不重命名已有文件。本仓库 `CLAUDE.md` 的明确命名约定继续适用。

既有 [TypeScript 规范分册决策](../../implemented/architecture/2026-10-22-ts-standards-reference-split.md) 持有专项命名约定，本次不改变该决定；其他已有笔记不持有本主题决策。

## Alternatives considered

- **为 C# 增加例外（未采用）**：改动小、能直接处理当前反馈，但其他语言仍会受到全局风格影响，并需要持续追加例外。
- **通用入口只规定命名依据（采用）**：由项目规范和所属技术栈决定具体风格，覆盖混合技术栈；代价是执行者需先核对目标项目，而不能直接套用一个默认大小写规则。

## Verification

- 对照修改前的 `HEAD:rules/main.md`，核对只有 §2.1 发生变化，并检查项目明确规范、无明确规范和混合技术栈三种情况的处理依据。
- 使用 `node scripts/count-tokens.mjs` 更新并复核 README 数字，确认其他规范和既有文件路径不变；运行 `git diff --check`。
- 从仓库根目录使用 Node.js 24 运行已加载笔记 skill 的目录、格式和归档校验脚本，不增加项目依赖。

## Consequences

- 通用入口不再把某种技术栈的大小写风格施加到所有语言，具体风格由项目和专项规范确定。
- 执行者需要核对文件或模块的技术栈归属及项目规则；这是行为规范的调整，不会自动修正已有项目中的文件名。
- 后续若仍出现跨技术栈套用命名，应核对项目规则和专项 skill 的适用范围，不在通用入口不断追加语言例外。
